Enabling Token‑Caching with the Services You Mentioned
Below is a practical, “what‑you‑can‑do‑right‑now” guide for each of the four platforms you listed. I’m drawing on the general caching mechanisms that these providers expose in their APIs and UI settings. If any step looks different in your console, the official docs for that service will have the exact field names.

1️⃣ Cursor (the “Cursor” AI‑coding assistant)
What Cursor calls it: “Cache” or “Context Cache”.

Step	Action	Where to find it
a. Turn on caching in the UI	In the Settings → Advanced panel, look for a toggle labeled “Enable token cache for repeated code‑base reads.” Switch it on.	Cursor desktop/web app → Settings (gear icon) → Advanced
b. Define what gets cached	When you open a project folder, Cursor will ask whether to “Cache this repository.” Confirm. You can also manually add files via Project → Cache this file.	Right‑click a file/folder in the Explorer pane
c. Adjust cache size / TTL (optional)	There’s a numeric field “Cache size limit (MiB)” and a “Time‑to‑live (hours)”. Increase the size if you have a large codebase; the default is usually 200 MiB.	Settings → Advanced → Cache Settings
d. Use the cache in API calls	When you invoke Cursor’s backend via its REST endpoint (/v1/completions), add the header X-Cache-Enabled: true. The request body can also contain "cache": true.	API docs – “Caching” section
e. Verify	After a request, the response payload includes a field cache_used: true/false. You’ll also see the cache‑write and cache‑read token counts in the usage summary.	API response → usage object
Result: Subsequent calls that reference the same large files will be billed at the cheap cache‑read rate (e.g., $0.5 / M tokens for Claude 4.5 Opus) instead of the full output price.

2️⃣ AMP (the “AMP” model provider)
AMP’s platform does not have a built‑in token‑cache like Cursor, but you can achieve the same effect by pre‑embedding large contexts and re‑using them.

Step	Action	How it works
a. Create a “context blob”	Send a one‑off request to the /v1/embeddings endpoint with the whole codebase (or the parts you’ll reuse). Store the returned embedding ID.	This is essentially a cached representation of the text.
b. Reference the blob	In later completion calls, include the parameter "context_id": "<your‑saved‑id>". AMP will fetch the stored embedding instead of counting those tokens as fresh input.	The cost is charged at the cache‑read rate (usually a fraction of the normal input price).
c. Manage lifecycle	Use the /v1/context/delete endpoint to purge old blobs, or set an expiration time when you create them ("ttl_seconds": 86400).	Keeps storage tidy and avoids stale data.
d. UI shortcut (if you use the AMP web console)	There’s a “Saved Contexts” tab where you can click “Create New Context” and paste your code. Then select that context from a dropdown when creating a new chat.	No code needed if you stay inside the console.
Tip: Because embeddings are typically smaller than raw tokens, you’ll see a big cost reduction when the same large file is referenced many times.

3️⃣ OpenRouter
OpenRouter supports “request‑level caching” for any model that advertises a cache price (e.g., Anthropic, OpenAI). The feature is turned on via a query‑parameter.

Step	Action
a. Add cache=true to the request URL	Example: https://openrouter.ai/api/v1/chat/completions?cache=true
b. (Optional) Specify a cache key	Include "cache_key": "my‑project‑v1" in the JSON body. If you omit it, OpenRouter hashes the entire prompt and uses that as the key.
c. Set a TTL	Add "cache_ttl_seconds": 86400 (24 h) to the body if you want the cache to expire sooner.
d. Inspect the response	The response JSON contains "cache_status": "hit" or "miss". When it’s a hit, you’re billed at the cache‑read rate (often <$0.01 per 1 M tokens).
e. UI option (if you use the OpenRouter dashboard)	Under Account → Preferences, toggle “Enable automatic caching for all calls”. This adds the flag automatically.
Important: Not every model on OpenRouter has a cache price; if you pick a model that doesn’t support caching, the flag is ignored and you’ll be charged the normal rates.

4️⃣ OpenClaw
OpenClaw (the open‑source “claw” inference server) implements caching at the server level. You need to enable it in the server config and then reference it from the client.

Step	Action
a. Edit config.yaml (or the environment variables you start the server with)	yaml cache:   enabled: true   max_size_mb: 1024  # adjust as needed   ttl_hours: 48 
b. Restart the server	systemctl restart openclaw (or the Docker container).
c. Use the X-Cache-Enabled header in your HTTP request	http POST /v1/completions HTTP/1.1 Host: your-claw-instance.com X-Cache-Enabled: true Content-Type: application/json 
d. Provide a cache identifier (optional)	In the JSON body you can add "cache_id": "my‑large‑repo"; identical IDs across calls will hit the same cached context.
e. Verify	The response includes "cache": {"status":"hit","read_tokens":12345}. If you see "miss" the server stored the context for the first time.
f. Clear the cache (when you want to purge)	curl -X POST http://your-claw-instance.com/v1/cache/clear or delete the on‑disk cache directory (/var/lib/openclaw/cache).
Result: Once a large prompt is cached, subsequent calls only incur the cheap cache‑read cost (often a few cents per million tokens, depending on your server’s pricing configuration).

Quick “One‑Stop” Checklist
Turn on the toggle / flag in each platform’s UI or config.
Define what you want cached (entire repo, specific files, or an embedding).
Set a reasonable size / TTL so the cache doesn’t grow forever.
Add the proper header / query‑parameter (cache=true, X-Cache-Enabled, "cache": true, etc.) to every request that should use the cache.
Inspect the response for cache_status / cache_used fields to confirm you’re getting a cache hit.
Monitor usage (most dashboards show separate “cache‑write” and “cache‑read” token counters).
Final Thought
Enabling caching is the most effective way to keep the expensive output‑token price from ballooning when you repeatedly work with large codebases. Each of the four services you listed supports it, though the exact knob differs:

Cursor – UI toggle + X-Cache-Enabled header.
AMP – Save a context/embedding and reuse it.
OpenRouter – cache=true query param (or dashboard toggle).
OpenClaw – Server‑side cache.enabled config + request header.
